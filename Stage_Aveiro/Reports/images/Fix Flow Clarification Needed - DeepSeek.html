FixFlow — Système de Gestion de Maintenance Vue d'ensemble du projet FixFlow est une application web de gestion de maintenance industrielle. Elle permet aux opérateurs de signaler des pannes machines, aux techniciens de les traiter, et aux administrateurs de superviser l'ensemble du système. Le projet suit une architecture client-serveur avec un backend API REST et un frontend SPA (Single Page Application). Stack Technique Backend Laravel 13 (PHP 8.4+) Laravel Sanctum — authentification par token API SQLite (base de données par défaut, configurable MySQL/PostgreSQL) Eloquent ORM Frontend React 19 + Vite 8 Tailwind CSS 4 React Router DOM 7 Axios (via wrapper personnalisé) Bibliothèques clés : html5-qrcode, sonner, motion, lucide-react, date-fns Architecture Le projet est monorepo : le frontend React vit dans fixflow-backend/client/ et Vite proxifie les appels /api vers Laravel en développement. fixflow-backend/ ├── app/Http/Controllers/ → AuthController, TiketController, MachineController, UserController ├── app/Models/ → User, Ticket, Machine, Log ├── routes/api.php → Toutes les routes API ├── database/ │ ├── migrations/ → Schéma de la base │ └── seeders/ → Données de test └── client/src/ ├── pages/ → worker/, technician/, admin/ ├── components/ → TicketForm, QRScanner, MachineCard, + 72 composants UI ├── context/ → AuthContext, TicketContext, MachineContext, LanguageContext ├── layouts/ → WorkerLayout, TechnicianLayout, AdminLayout └── lib/ → api.js, translations.js, utils.js Rôles et Fonctionnalités Worker (Opérateur) Scanner un QR code machine pour signaler une panne Rechercher une machine par nom, ID ou localisation Créer un ticket avec description, priorité (low/medium/high/critical) et photo Suivre ses tickets soumis Technicien Tableau de Authentification Laravel Sanctum avec tokens Bearer. Le token est stocké dans localStorage (fixflow_token) et envoyé dans chaque requête. Les routes frontend sont protégées par un composant ProtectedRoute qui vérifie le rôle de l'utilisateur. Comptes de test seedés : worker@fixflow.com / password tech@fixflow.com / password admin@fixflow.com / password Points techniques notables Polling : les tickets se rafraîchissent toutes les 10 secondes (pas de WebSocket) Alertes sonores : le technicien reçoit un son (alert.mp3) pour les nouveaux tickets non assignés, avec gestion du déblocage audio navigateur Internationalisation : 3 langues (EN, FR, AR) avec support RTL pour l'arabe Dark mode : toggle thème persisté en localStorage QR Code : scan via html5-qrcode pour identifier les machines rapidement Typo connue : la table s'appelle tikets (sans 'c') — cohérent dans tout le code Logging : chaque action (création, assignation, changement de statut, résolution) est enregistrée dans la table logs
